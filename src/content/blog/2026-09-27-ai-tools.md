오늘 Hacker News는 유독 "AI와 함께 어떻게 일할 것인가"에 대한 메타적인 논의가 눈에 띄었습니다. LLM 래퍼 같은 실용적인 도구부터, 프로그래밍의 즐거움을 어떻게 지킬지에 대한 철학적 토론, 그리고 Mistral CEO의 AI 통제 가능성 발언까지 폭넓게 다뤄졌습니다. 한편으로는 레거시 DOS 시스템 유지보수나 VS Code 버그 같은 지극히 현실적인 개발자 일상 이야기도 여전히 큰 공감을 얻었습니다.

## 아직도 DOS 머신을 돌리는 회사들이 있다
Ask HN 스레드에서 한 개발자가 "사업이 DOS 머신에 의존하고 있어서 아직도 유지보수 중이냐"고 물었고, 257개의 댓글이 달리며 공장 설비 제어, 오래된 POS 시스템, 산업용 임베디드 장비 등 실제 사례들이 쏟아졌습니다. 새 시스템으로 마이그레이션하는 비용과 리스크가 너무 커서 수십 년 된 시스템을 그대로 유지하는 현실이 생생하게 드러납니다. AI/LLM이 코드 작성을 자동화하는 시대에도, 정작 현장에는 손도 못 대는 레거시 시스템이 여전히 많다는 걸 보여주는 흥미로운 반례입니다.
https://news.ycombinator.com/item?id=49848955

## 위치를 직접 지정하는 다이어그램 언어, Reladraw
Reladraw는 자동 레이아웃에 의존하지 않고 사용자가 다이어그램의 각 요소를 직접 배치할 수 있는 텍스트 기반 다이어그램 언어입니다. Mermaid 같은 자동 배치 도구들이 종종 원치 않는 레이아웃을 만들어내는 문제를 정면으로 해결하려는 접근입니다. 코드로 다이어그램을 관리하면서도 시각적 통제권을 포기하고 싶지 않은 개발자들에게 실용적인 대안이 될 수 있습니다.
https://github.com/reladraw/reladraw

## LLM 시대에도 프로그래밍을 즐겁게 하는 법
Haskell Discourse에 올라온 이 글은 LLM이 코드를 대신 짜주는 시대에 프로그래머로서의 즐거움과 성장을 어떻게 지킬 것인지 고민합니다. 저자는 문제 해결 자체의 재미, 언어와 타입 시스템을 깊이 이해하는 즐거움 등 LLM이 대체하기 어려운 영역에 집중할 것을 제안합니다. 208개의 댓글에서는 "AI에게 위임할 부분"과 "직접 해야 즐거운 부분"을 어떻게 나눌지에 대한 다양한 의견이 오갔습니다. 생산성 도구로서의 AI와 개인의 성취감 사이에서 균형점을 찾으려는 개발자들에게 생각할 거리를 던져줍니다.
https://discourse.haskell.org/t/how-to-keep-enjoying-programming-in-a-world-of-llms/14705

## 비전 모델까지 지원하는 초경량 LLM 래퍼
저자는 단 하나의 함수로 텍스트뿐 아니라 비전 모델까지 다룰 수 있는 LLM 래퍼를 만들었습니다. 거대한 SDK나 프레임워크 없이도 여러 LLM 제공사의 API를 최소한의 코드로 통합해서 쓸 수 있다는 게 핵심입니다. 프로덕션에 무거운 라이브러리를 붙이기보다 필요한 만큼만 직접 짜서 쓰고 싶은 개발자들에게 참고할 만한 코드입니다.
http://allanrbo.blogspot.com/2026/09/a-jev-like-wrapper-for-llms-including.html

## Too AI; Didn't Read
"Too AI; Didn't Read"는 AI가 생성한 콘텐츠가 범람하는 요즘, 그런 콘텐츠를 걸러내거나 표시해주는 것을 지향하는 프로젝트로 보입니다. 111개의 댓글에서는 AI 생성 콘텐츠를 구분하는 것의 실효성과 한계에 대한 논쟁이 이어졌습니다. AI 콘텐츠 홍수 속에서 "무엇을 읽을 가치가 있는가"를 다시 고민하게 만드는 시도라는 점에서 주목할 만합니다.
https://www.tai-dr.com/

## Mistral CEO: "AI는 소프트웨어다, 통제할 수 있다"
Mistral AI의 CEO Arthur Mensch가 르몽드와의 인터뷰에서 AI를 신비화하지 말고 결국은 통제 가능한 소프트웨어로 봐야 한다는 입장을 밝혔습니다. 그는 AI의 위험성을 과장하는 담론과 유럽의 AI 주권 문제에 대해서도 언급했습니다. 153개의 댓글에서는 "AI가 정말 통제 가능한 소프트웨어인가"에 대한 회의적 시각과 지지하는 시각이 팽팽하게 맞섰습니다. AI 안전성 논의가 추상적 두려움에서 벗어나 엔지니어링 문제로 다뤄져야 한다는 관점을 대표하는 발언이라 주목됩니다.
https://www.lemonde.fr/en/economy/article/2026/09/24/arthur-mensch-ceo-of-french-start-up-mistral-ai-ai-is-software-it-can-be-controlled_6757890_19.html

## VS Code 에디터에 퍼진 border-radius 버그
VS Code GitHub 이슈에서 최근 업데이트 이후 에디터 곳곳에 의도치 않은 둥근 모서리(border-radius)가 적용되는 버그가 보고되었습니다. 시각적으로 사소해 보이지만 코드 하이라이팅, 선택 영역 등 여러 UI 요소에 영향을 미쳐 51개의 댓글에서 불편함을 토로하는 개발자들이 많았습니다. 매일 쓰는 도구의 디테일이 개발자 경험에 얼마나 큰 영향을 미치는지 보여주는 사례입니다.
https://github.com/microsoft/vscode/issues/338035

## Claude Code로 체스 기보 분석하기
개발자 brumar는 Claude Code의 스킬 기능을 활용해 자신의 체스 게임 기보를 분석해주는 도구를 공개했습니다. 대국 후 실수한 수와 그 이유를 LLM이 짚어주는 방식으로, 체스 엔진 분석에 자연어 설명을 더한 형태입니다. Claude Code의 스킬 시스템이 코딩 외의 취미 영역에서도 실용적으로 활용될 수 있음을 보여주는 좋은 예시입니다.
https://github.com/brumar/chess-postmortem-skills
