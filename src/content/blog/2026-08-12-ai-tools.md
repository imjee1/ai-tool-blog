오늘 Hacker News에서는 AI 서비스의 "블랙박스"를 열어보려는 시도들이 두드러졌습니다. 프로프라이어터리 LLM API에서 추론 과정을 역추적하는 연구, GitHub Copilot의 실제 네트워크 트래픽을 분석한 글, 그리고 Anthropic이 직접 공개한 Claude의 수학 능력 연구까지 - AI 도구를 그냥 쓰는 것에서 "어떻게 작동하는지 알고 쓰는 것"으로 관심이 옮겨가는 흐름이 보입니다.

## Stealing Reasoning Traces from Proprietary LLM APIs

프로프라이어터리 LLM API(예: OpenAI, Anthropic 등)가 최종 답변만 노출하고 내부 추론 과정(reasoning trace)은 숨기더라도, 특정 기법을 통해 이 숨겨진 추론 흔적을 추출할 수 있다는 걸 보여주는 프로젝트입니다. API 응답의 타이밍이나 토큰 패턴 같은 부수 정보를 활용해 모델이 실제로 어떤 사고 과정을 거쳤는지 재구성하는 방식을 다룹니다. AI 벤더들이 "추론 과정은 비공개"라고 못박아도 실제로는 완전히 감출 수 없다는 걸 실증한 사례라 주목할 만합니다.

원문: https://stolen-thoughts.com/

## How Claude marks AI-generated content

Anthropic이 Claude가 생성한 콘텐츠에 워터마크나 메타데이터를 어떻게 표시하는지 공식 문서로 설명한 글입니다. AI 생성 콘텐츠 식별이 규제와 신뢰 문제로 점점 중요해지는 가운데, 주요 벤더가 자신들의 접근 방식을 투명하게 공개한 셈입니다. AI 콘텐츠 판별 논쟁이 뜨거운 시점에 대형 AI 회사의 공식 입장을 확인할 수 있다는 점에서 의미가 있습니다.

원문: https://support.claude.com/en/articles/16266773-how-claude-marks-ai-generated-content

## Learning more about Claude's mathematical capabilities

Anthropic이 리만 제타 함수 관련 문제를 통해 Claude의 수학적 추론 능력을 분석한 연구 결과입니다. 단순히 정답을 맞히는지가 아니라, 모델이 실제로 수학적 개념을 얼마나 깊이 이해하고 있는지, 그리고 어디서 한계를 보이는지를 살펴봅니다. LLM의 추론 능력에 대한 막연한 기대와 실제 성능 사이의 간극을 벤더가 직접 검증한 자료라는 점에서 참고할 가치가 있습니다.

원문: https://www.anthropic.com/research/riemann-zeta

## What I learned by putting GitHub Copilot behind a MitM proxy

저자가 GitHub Copilot의 네트워크 트래픽을 MitM(Man-in-the-Middle) 프록시로 가로채 실제로 어떤 데이터가 오가는지 분석한 글입니다. Copilot이 코드 컨텍스트를 얼마나 많이, 어떤 형태로 서버에 전송하는지 등 평소 알기 어려운 내부 동작을 직접 확인한 사례입니다. 회사에서 Copilot 같은 AI 코딩 도구를 도입할 때 보안·프라이버시 검토에 실질적으로 도움이 되는 내용입니다.

원문: https://www.lighthousenewsletter.com/p/i-put-github-copilot-behind-a-mitm

## Apple Silicon and macOS VMs: Faster LLM Inference with llama.cpp

Apple Silicon 기반 macOS 가상머신에서 GPU passthrough를 활용해 llama.cpp의 LLM 추론 속도를 높이는 방법을 다룬 글입니다. 일반적으로 VM 환경에서는 GPU 가속이 제한적인데, 이를 우회해 네이티브에 준하는 성능을 끌어내는 기술적 접근을 설명합니다. 로컬에서 LLM을 돌리는 개발자, 특히 macOS 가상화 환경을 쓰는 이들에게 실용적인 팁이 될 만합니다.

원문: https://github.com/trycua/cua/blob/main/blog/gpu-passthrough-macos-vms.md
