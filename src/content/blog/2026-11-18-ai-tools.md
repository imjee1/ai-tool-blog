오늘은 OpenAI와 Microsoft가 나란히 신규 모델/코딩 도구를 발표하면서 AI 경쟁이 다시 한번 뜨거워진 하루였습니다. 동시에 "AI 코딩 에이전트가 정말 생산성을 높이는가"에 대한 실증적 회의론도 함께 떠올랐습니다. 여기에 jQuery의 깜짝 메이저 업데이트와 공급망 보안 사고까지, 개발자라면 챙겨볼 이슈가 다양했던 하루입니다.

## GPT-6.2 Astra and Sol
OpenAI가 새로운 모델 라인업 GPT-6.2 Astra와 Sol을 공개했습니다. HN에서 721개의 댓글이 달릴 정도로 반응이 뜨거웠는데, 성능 개선 폭과 공개 방식을 둘러싼 논쟁이 이어지고 있습니다. 모델 세대가 빠르게 갱신되는 만큼 실제 워크플로우에 어떤 영향을 주는지 지켜볼 필요가 있습니다.
- 가장 많은 관심을 받은 소식인 만큼 업계 방향성을 가늠하는 데 참고할 만합니다.
- https://openai.com/index/introducing-gpt-6-2-astra-sol/

## MAI Code 2 and Code 2 Flash
Microsoft AI가 자체 코딩 전용 모델 MAI Code 2와 경량화 버전 Code 2 Flash를 발표했습니다. OpenAI 의존도를 낮추고 자체 코딩 모델 역량을 키우려는 Microsoft의 행보로 해석됩니다. Flash 버전은 속도와 비용 효율을 노린 것으로 보입니다.
- 코딩 어시스턴트 시장에서 Microsoft의 독자 노선이 본격화되는 신호로 주목할 만합니다.
- https://microsoft.ai/news/introducing-mai-code-2-and-mai-code-2-flash/

## How the Claude Code team thinks about verification
Anthropic의 Claude Code 팀이 AI가 생성한 코드를 어떻게 검증하는지에 대한 내부 접근법을 공유했습니다. 단순히 코드가 작동하는지뿐 아니라 의도한 대로 동작하는지 검증하는 체계를 다루고 있어 실무에 적용할 만한 인사이트가 많습니다. 216개 댓글에서 실제 적용 경험을 공유하는 논의도 활발합니다.
- AI 코딩 도구를 팀에 도입하려는 개발자라면 검증 프로세스 설계에 참고할 가치가 있습니다.
- https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/

## jQuery 4.1.0
오랜만에 jQuery 메이저 업데이트가 등장했습니다. 레거시 코드베이스를 유지보수하는 개발자들에게는 여전히 중요한 소식이며, 변경 사항과 호환성 이슈에 대한 논의가 HN에서 활발히 오갔습니다.
- AI 뉴스에 밀려 조용히 지나가기 쉽지만, 프론트엔드 레거시 운영 중이라면 체크할 필요가 있습니다.
- https://github.com/jquery/jquery/releases/tag/4.1.0

## Microsoft's ONNX Runtime has disappeared from GitHub
Microsoft의 ONNX Runtime 저장소가 GitHub에서 일시적으로 사라지는 사건이 발생했습니다. 원인은 명확히 밝혀지지 않았지만, 많은 ML 프로젝트가 의존하는 핵심 라이브러리라 커뮤니티의 우려가 컸습니다.
- 주요 오픈소스 인프라의 가용성 리스크를 환기시키는 사례입니다.
- https://github.com/microsoft/onnxruntime

## Not Everything Needs an LLM
PostHog 블로그에서 모든 의사결정 로직에 LLM을 쓰는 것이 능사가 아니라는 주장을 제기했습니다. 간단한 규칙 기반 로직이나 전통적인 ML 모델이 더 적합한 경우를 구체적으로 짚으며, LLM 과잉 적용에 대한 경계심을 드러냅니다. 비용과 지연시간, 예측 가능성 측면에서 설득력 있는 사례들을 제시합니다.
- AI를 어디에 써야 할지 고민 중인 팀이라면 균형 잡힌 시각을 얻을 수 있습니다.
- https://newsletter.posthog.com/p/decision-models

## Harvard researchers find AI coding agents shifted the bottleneck to code review
하버드 연구진이 AI 코딩 에이전트 도입 후 개발 병목이 코드 작성에서 코드 리뷰로 이동했다는 연구 결과를 발표했습니다. 코드 생성 속도는 빨라졌지만 사람이 이를 검토하고 신뢰하는 과정이 새로운 병목이 되고 있다는 분석입니다. 132개 댓글에서 실제 팀 운영 경험을 공유하며 공감하는 반응이 많았습니다.
- AI 코딩 도구 도입 효과를 단순 생산성 수치로만 판단하기 어렵다는 점을 보여주는 중요한 연구입니다.
- https://complexdiscovery.com/harvard-researchers-find-ai-coding-agents-shifted-the-bottleneck-to-code-review/

## Optimizely hack infected CNN, Fox News, BBC, Salesforce sites with malware
웹 최적화 도구 Optimizely를 통한 공급망 공격으로 CNN, Fox News, BBC, Salesforce 등 대형 사이트들이 악성코드에 감염된 사건이 보도됐습니다. 서드파티 스크립트 하나가 다수의 유명 사이트에 영향을 미쳤다는 점에서 공급망 보안의 취약성을 다시 한번 드러냈습니다.
- 외부 스크립트/SaaS 의존도가 높은 서비스를 운영한다면 보안 점검이 필요한 사례입니다.
- https://www.bleepingcomputer.com/news/security/optimizely-supply-chain-attack-delivers-malware-to-cnn-fox-news-bbc-salesforce-sites/
