오늘 Hacker News는 Claude Code 관련 소식 두 건이 상위권을 차지했다. 하나는 보안 취약점, 다른 하나는 사용량 제한 축소인데 공교롭게 같은 날 논의되며 개발자들의 관심이 집중됐다. 여기에 AI 에이전트가 실수로 사용자 데이터를 삭제한 사례, 그리고 YC S26 배치의 신규 스타트업들도 함께 소개됐다.

## Claude Code Opus 5 Auto Mode 우회 취약점

보안 연구자가 Claude Code의 Opus 5 Auto Mode에서 안전장치를 우회할 수 있는 방법을 찾아내 공개했다. 프롬프트 인젝션 계열 기법으로 에이전트가 자동 실행 모드에서 의도치 않은 동작을 하도록 유도할 수 있다는 내용이다. Auto Mode처럼 사람의 승인 없이 코드를 실행하는 기능이 늘어날수록 이런 우회 사례가 계속 나올 수밖에 없다는 점에서, 에이전트형 코딩 도구를 프로덕션에 붙이기 전 반드시 참고할 만한 글이다.

- https://embracethered.com/blog/posts/2026/breaking-claude-code-opus-5-and-automode/

## Claude Code 주간 사용 한도 17% 축소

Anthropic이 Claude Code의 주간 사용 한도를 기존 대비 17% 줄인다고 공지했다. 트위터를 통해 알려진 소식으로, 구체적인 배경 설명 없이 발표되면서 헤비 유저들 사이에서 불만이 나오고 있다. 유료 요금제를 쓰는 개발자 입장에서는 워크플로 설계에 직접 영향을 주는 변경이라 커뮤니티 반응이 뜨거웠다.

- https://twitter.com/ClaudeDevs/status/2093742322525810912

## Meta 보안 연구원, AI 에이전트가 이메일 삭제

Meta의 한 보안 연구원이 사용하던 AI 에이전트가 작업 도중 실수로 이메일을 삭제하는 사고가 발생했다. 에이전트에게 메일함 정리 같은 권한을 부여했을 때 발생할 수 있는 대표적인 리스크 사례로 언급되고 있다. AI 에이전트에 실제 계정 접근 권한을 줄 때 되돌릴 수 없는 작업에 대한 안전장치가 얼마나 허술한지 보여주는 사례라 눈여겨볼 만하다.

- https://au.pcmag.com/ai/116091/meta-security-researchers-ai-agent-accidentally-deleted-her-emails

## Continuous Diffusion Language Models (CDLMs)

이산적인 토큰 대신 연속 공간에서 확산(diffusion) 방식으로 언어를 생성하는 모델에 대한 기술 해설 글이다. 저자는 기존 autoregressive LLM과 다른 생성 패러다임으로서 CDLM의 원리와 최근 연구 흐름을 정리했다. 언어 모델 아키텍처의 다음 세대를 가늠해보고 싶은 개발자에게 좋은 입문 자료다.

- https://sander.ai/2026/08/24/continuous-dlms.html

## Launch HN: Almanac (YC S26) – 회사를 아는 AI

Almanac은 사내 문서, 슬랙 대화, 코드 등 회사 내부 데이터를 학습해 조직 특화 질문에 답하는 AI 어시스턴트를 표방하는 YC S26 스타트업이다. 일반 LLM이 놓치는 회사 고유의 맥락과 용어를 이해시키는 데 초점을 맞췄다. 사내 지식 검색·온보딩 자동화 수요가 꾸준한 만큼 실제 도입 사례가 어떻게 쌓일지 지켜볼 만하다.

- https://usealmanac.com/

## Launch HN: Hebbian Robotics (YC S26) – 로보틱스 데이터 파이프라인

Hebbian Robotics는 로봇 학습에 필요한 대규모 데이터 파이프라인을 구축·관리하는 오픈소스 도구 hflow를 공개했다. 로봇 데이터 수집, 정제, 라벨링 과정을 표준화해 확장 가능하게 만드는 것이 목표다. 로보틱스 분야에서도 데이터 인프라가 병목이 되고 있다는 점에서 관련 업계 종사자라면 참고할 만하다.

- https://github.com/Hebbian-Robotics/hflow
