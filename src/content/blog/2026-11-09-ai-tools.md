오늘 Hacker News는 Claude Code를 중심으로 한 이야기로 가득했다. 한쪽에서는 개인 개발자가 Claude에서 Pi로 갈아탄 이유를 공유했고, 다른 한쪽에서는 골드만삭스가 보안 우려로 Claude Code를 거둬들였다는 소식과 실제 보안 취약점이 발견됐다는 리포트가 동시에 터졌다. 동시에 "나는 LLM을 쓰지 않겠다"는 반대 목소리와, GPU 없이 거대 모델을 돌리는 로컬 추론 프로젝트도 함께 화제가 되었다.

### Goodbye Claude, hello Pi
한 개발자가 Claude를 떠나 Pi(Inflection AI의 어시스턴트)로 옮긴 이유를 정리한 글이다. 글쓴이는 Claude의 응답 스타일이나 제약, 비용 구조 등에 불만을 느꼈고 Pi의 대화 경험이 자신의 작업 흐름에 더 잘 맞았다고 설명한다. 435개의 댓글이 달릴 만큼 AI 어시스턴트 선택 기준에 대한 개발자들의 공감대와 반박이 뜨겁게 오갔다.
AI 도구 선택이 더 이상 "최고 성능"만의 문제가 아니라 개인 워크플로우 궁합의 문제로 넘어가고 있음을 보여준다.
https://caleb.software/posts/claude-to-pi.html

### Goldman Sachs is pulling Claude Code from its bankers and traders
골드만삭스가 자사 뱅커와 트레이더들에게 제공하던 Claude Code 접근 권한을 회수했다는 보도다. 구체적인 사유는 명확히 공개되지 않았지만, 금융권 특유의 보안·컴플라이언스 민감도와 맞물려 해석되고 있다. 같은 날 터진 Claude Code의 보안 취약점 이슈와 겹치며 더 큰 주목을 받았다.
대형 금융기관이 AI 코딩 도구 도입을 얼마나 신중하게(혹은 변덕스럽게) 다루는지 보여주는 사례다.
https://www.thestateofai.com/news/goldman-sachs-claude-code-traders-bankers

### Claude Code's "Don't Ask Again" exposes passwords in 1,122 public GitHub files
Apiiro 보안 연구팀이 Claude Code의 "다시 묻지 않기(Don't Ask Again)" 옵션으로 인해 실제 패스워드와 시크릿이 포함된 파일이 커밋되어, 공개 GitHub 저장소 1,122곳에서 노출된 사례를 발견했다고 밝혔다. 에이전트가 반복되는 승인 요청을 건너뛰도록 설정했을 때, 민감 정보가 포함된 파일도 별다른 확인 없이 커밋·푸시된 것이 원인으로 지목된다. 398개 댓글에서는 코딩 에이전트의 기본 안전장치 설계 전반에 대한 논쟁이 이어졌다.
AI 코딩 에이전트의 편의 기능이 보안 사고로 직결될 수 있다는 걸 실증적으로 보여준 사례라 의미가 크다.
https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again

### Llama-modchip: 284B DeepSeek on 64GB RAM, no GPU
GPU 없이 64GB RAM만으로 2840억 파라미터 규모의 DeepSeek 모델을 구동할 수 있게 해주는 오픈소스 프로젝트다. 메모리 매핑과 양자화, 효율적인 디스크 I/O 전략을 활용해 거대 모델을 일반 소비자 하드웨어에서도 실행 가능하게 만든 것이 핵심이다. 159개의 댓글에서는 실제 추론 속도와 실용성에 대한 검증 논의가 활발했다.
클라우드 API 의존 없이 초거대 모델을 로컬에서 돌리려는 시도가 점점 현실화되고 있음을 보여준다.
https://github.com/synchopate/llama-modchip

### KetchUp – Open-source SketchUp alternative built with Rust and WebGPU
Rust와 WebGPU로 만든 오픈소스 3D 모델링 툴로, 상용 소프트웨어 SketchUp의 대안을 지향한다. 웹 브라우저에서 바로 동작하는 네이티브급 3D 렌더링 성능을 보여주며, 직관적인 UI를 통해 간단한 건축/설계 모델링을 지원한다. AI 관련 주제는 아니지만 Rust/WebGPU 생태계의 성숙도를 보여주는 사례로 많은 개발자의 관심을 끌었다.
웹 기반 그래픽 툴링이 네이티브 앱의 영역을 빠르게 대체하고 있다는 신호다.
https://ketchup3d.github.io/app/

### GitHub Down Again?
GitHub 서비스 장애 당시, 사람들이 Linus Torvalds의 Linux 커널 저장소 링크를 공유하며 상태를 확인하던 스레드다. 특별한 기술 콘텐츠보다는 장애 발생 시 개발자 커뮤니티의 반응과 "또야?"라는 피로감을 담은 가벼운 토론이었다. 127개 댓글에는 각자 겪은 장애 경험과 대체 호스팅 서비스에 대한 농담 섞인 제안이 오갔다.
핵심 인프라에 대한 의존도가 얼마나 큰지, 그리고 장애 시 커뮤니티가 얼마나 빠르게 반응하는지를 보여주는 일상적 사례다.
https://github.com/torvalds/linux

### Why I will not be using LLMs in my coding
한 개발자가 자신의 코딩 작업에 LLM을 사용하지 않기로 한 이유를 설명한 에세이다. 코드 이해도 저하, 학습 기회 상실, 장기적인 기술 숙련도에 대한 우려를 주요 근거로 들고 있다. 221개의 댓글에서는 찬반 양측의 경험담과 반박이 길게 이어지며 AI 코딩 도구에 대한 양극화된 시각을 드러냈다.
AI 도구 과잉 수용에 대한 반작용이 커뮤니티 내에서 점점 뚜렷해지고 있다는 걸 보여준다.
https://www.polso.info/why-i-will-not-be-using-llms-coding

### Silicon Valley Promises AI Will Cure Disease. Drugmaker CEOs Aren't Buying It
WSJ 기사로, 실리콘밸리가 AI를 통한 신약 개발과 질병 치료 혁신을 자신하는 반면 실제 제약회사 CEO들은 이에 회의적인 입장을 보인다는 내용을 다룬다. AI 모델이 분자 설계나 초기 후보물질 발굴에는 도움을 주지만, 임상시험·규제·실제 효능 검증 단계에서는 여전히 기존 방식이 필요하다는 현실적 지적이 담겼다. 108개 댓글에서는 AI 신약개발의 실제 성과와 과장된 기대 사이의 간극에 대한 논의가 이어졌다.
AI의 산업별 실제 적용 속도와 기대치 사이의 괴리를 짚어주는 기사라 눈여겨볼 만하다.
https://www.wsj.com/tech/ai/silicon-valley-promises-ai-will-cure-disease-drugmaker-ceos-arent-buying-it-5218511c
