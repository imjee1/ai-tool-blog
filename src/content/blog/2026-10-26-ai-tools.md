오늘 Hacker News는 "거대 LLM이 항상 답은 아니다"라는 메시지로 요약된다. 10년 된 작은 모델이 최신 LLM을 이기는 사례부터, LLM 가격이 몇 달 만에 80% 급락한 이유, 그리고 오픈소스 커뮤니티가 AI 생성 코드에 선을 긋기 시작한 사건까지 — AI를 둘러싼 기대와 반작용이 동시에 드러난 날이었다. 한편에서는 레트로 게임 엔진 복원이나 새 프로그래밍 언어처럼 묵묵히 만드는 사람들의 이야기도 눈에 띈다.

## 10년 된 CNN이 최신 LLM보다 피부암 진단을 잘한다
2015년경 만들어진 작은 CNN 모델이 피부암 이미지 진단 테스트에서 GPT-4급 최신 LLM들보다 더 높은 정확도를 보였다는 분석 글이다. 저자는 범용 LLM이 이미지 분류라는 좁고 명확한 태스크에서는 특화 훈련된 작은 모델을 이기기 어렵다는 점을 데이터로 보여준다. "크고 일반적인 모델이 작고 전문화된 모델을 항상 대체할 수 있다"는 최근의 통념에 반박하는 사례라 주목할 만하다.
https://lynchlab.net/llm-skin-cancer

## fheroes2: 영웅들의 군대 2 엔진을 되살리는 오픈소스 프로젝트
`fheroes2`는 고전 전략 게임 Heroes of Might and Magic II의 게임 엔진을 깨끗하게 재구현한 오픈소스 프로젝트다. 원본 리소스 파일(그래픽, 사운드 등)은 그대로 쓰되 엔진 코드를 새로 작성해서 현대 OS에서도 원작 그대로 돌아가게 만든다. 오랜 기간 꾸준히 유지보수되며 커뮤니티가 활발한, 레거시 게임 보존의 대표 사례로 볼 수 있다.
https://github.com/ihhub/fheroes2

## GVS5H: Qwen3.8-27B 모델 5종을 돌려본 벤치마크 실험
`GVS5H`라는 이름의 하니스(테스트 프레임워크)를 사용해 Qwen3.8-27B 계열 모델 다섯 종이 "Fable 5"와 동등한 성능을 낸다는 것을 보여주는 저장소다. 구체적인 평가 방법론이나 Fable 5가 무엇을 가리키는지는 저장소를 직접 확인해야 정확히 알 수 있지만, 중소형 오픈 모델의 벤치마크 재현성에 관심 있는 개발자라면 들여다볼 만하다.
https://github.com/slee-persis/GVS5H

## JetBrains Thinkrail, 새 프로젝트 공개
JetBrains가 공개한 `Thinkrail`이라는 신규 프로젝트가 118개의 댓글을 모으며 화제가 됐다. 정확히 어떤 제품·도구인지는 저장소 설명만으로는 단정하기 어려우니, 세부 기능이 궁금하다면 원문 저장소와 토론 스레드를 직접 확인해보는 걸 추천한다. JetBrains라는 이름값 때문에 개발자 도구 생태계에 어떤 영향을 줄지 지켜볼 가치는 있다.
https://github.com/JetBrains/thinkrail

## 새 프로그래밍 언어 "Goose" 공개
Lobster, Cube 같은 언어를 만들어온 개발자 aardappel(Wouter van Oortmerssen)이 새 프로그래밍 언어 Goose를 공개했다. 공식 페이지에는 언어 설계 철학과 문법 예시가 정리되어 있다. 댓글이 1개뿐이라 아직 조용하지만, 신규 언어 설계에 관심 있는 사람들에게는 참고할 만한 자료다.
https://aardappel.github.io/goose/

## 제약이 창의성과 학습에 중요한 이유 (2023)
2023년에 쓰인 에세이로, 완전한 자유보다 명확한 제약이 있을 때 창의적 사고와 학습이 더 잘 일어난다는 주장을 다룬다. 프로그래밍 언어의 문법 제약, 게임의 규칙, 학습 커리큘럼의 구조 등을 예로 들며 "제한이 곧 방해물은 아니다"라는 관점을 제시한다. AI가 무엇이든 자동으로 생성해주는 시대에 개발자 스스로의 사고 틀을 어떻게 유지할지 고민하게 만드는 글이다.
https://ratfactor.com/cards/limitations

## OpenAI와 Anthropic, 몇 달 만에 LLM 가격 최대 80% 인하한 이유
minimaxir 블로그는 OpenAI와 Anthropic이 짧은 기간 동안 LLM API 가격을 최대 80%까지 내린 배경을 분석한다. 추론 비용 절감 기술의 발전, 경쟁 모델(오픈소스 및 중국계 모델 포함)의 압박, 사용량 기반 수익 모델로의 전환 압력 등을 복합적 원인으로 짚는다. API 비용에 민감한 개발자와 스타트업이라면 가격 정책 변화 추이를 참고할 만하다.
https://minimaxir.com/2026/10/cheap-llms/

## r/opensource, 1인 프로젝트와 LLM 사용 프로젝트 전면 금지
Reddit의 r/opensource 서브레딧이 1인 개발 프로젝트와 LLM을 활용해 만든 프로젝트의 게시를 전면 금지했다는 공지가 논쟁을 일으켰다. AI 생성 코드로 만든 저품질 "오픈소스" 홍보 게시물이 커뮤니티 신뢰도를 떨어뜨린다는 판단이 배경으로 보인다. 오픈소스 커뮤니티가 AI 생성 콘텐츠에 실질적으로 선을 긋기 시작한 사례로, 관련 커뮤니티 운영 방향을 가늠해볼 수 있는 사건이다.
https://www.reddit.com/r/opensource/comments/1xelcuf/your_tokens_arent_valuable_no_more_ai
