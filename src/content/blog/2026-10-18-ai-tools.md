오늘 Hacker News에서는 Anthropic의 투명성 관련 콘텐츠가 두 건이나 상위권에 올랐고, 동시에 "내 기기에서 LLM이 얼마나 빨리 돌아갈까"를 실험하는 커뮤니티 프로젝트들이 화제였다. 여기에 AI 자동화가 보안 경계를 넘나드는 사례까지, 오늘은 개발자가 직접 체감할 수 있는 이슈들이 많았다.

## Claude가 밝힌 ECDSA 커브의 기원

Anthropic이 Claude에게 ECDSA(타원곡선 전자서명 알고리즘)에서 쓰이는 표준 커브 파라미터들이 어떻게 만들어졌는지 설명하게 한 리서치다. NIST가 발표한 P-256 같은 커브들의 "임의의 시드값"이 실제로는 어떤 배경에서 선택됐는지, 암호학 역사와 신뢰 문제를 파고든다. 백도어 의혹이 꾸준히 제기돼온 민감한 주제를 LLM이 정리해낸다는 점에서 흥미롭다.

암호학에 익숙하지 않은 개발자도 AI가 복잡한 기술 역사를 어떻게 설명하는지 보는 재미가 있다.

링크: https://www.anthropic.com/research/ecdsa-curve-origins

## Claude Code 팀의 코드 리뷰 방식

Anthropic 내부에서 Claude Code를 만드는 팀이 자신들의 코드 리뷰 프로세스를 공개했다. AI가 작성한 코드가 늘어나는 상황에서 리뷰어의 역할이 어떻게 바뀌었는지, 그리고 Claude 자체를 리뷰 보조 도구로 어떻게 활용하는지를 다룬다. "코드 리뷰 병목"을 AI 기업이 실제로 어떻게 풀고 있는지 보여주는 사례 연구에 가깝다.

AI가 코드를 많이 짜는 시대에 리뷰 프로세스를 어떻게 재설계해야 하는지 고민하는 팀이라면 참고할 만하다.

링크: https://claude.dev/blog/solving-code-review-at-anthropic/

## 탈옥한 PS5에서 로컬 LLM 돌리기

llama.cpp를 포팅해서 jailbreak된 PlayStation 5에서 GGUF 포맷의 LLM을 네이티브로 실행하는 프로젝트다. 콘솔의 하드웨어 자원을 활용해 외부 서버 없이 추론을 돌릴 수 있게 만들었다. 게임기 하드웨어를 LLM 추론용으로 재활용하는 발상 자체가 해커 문화의 전형을 보여준다.

범용 하드웨어가 아닌 곳에서도 로컬 LLM 실행이 가능하다는 걸 보여주는 재미있는 증명이다.

링크: https://github.com/cobanov/PS5LM

## 하드웨어 사기 전에 LLM 속도를 미리 체감해보기

Llmspeed는 특정 하드웨어 스펙에서 로컬 LLM이 토큰을 얼마나 빨리 생성하는지 시뮬레이션해서 보여주는 웹 서비스다. GPU나 메모리를 업그레이드하기 전에 실제 체감 속도를 가늠해볼 수 있다. 로컬 LLM을 돌리려는 사람들에게 흔한 "이 정도 스펙이면 쓸만할까?"라는 질문에 직접 답을 준다.

값비싼 GPU를 지르기 전에 실제 토큰 생성 속도를 눈으로 확인할 수 있다는 점이 실용적이다.

링크: https://llmspeed.dev/

## 내가 허락하지 않은 통합이 내 시크릿을 스캔하고 있었다

Home Assistant 사용자가 자신도 모르게 설치된 통합(integration)이 시스템의 시크릿 값들을 스캔하고 있었다는 사실을 발견하고 올린 이슈다. 오픈소스 홈 자동화 플랫폼에서 서드파티 통합이 어떤 권한까지 가져갈 수 있는지에 대한 신뢰 문제를 제기했고, 댓글에서도 219개의 활발한 논의가 이어졌다. 자동화 도구와 AI 기반 통합이 늘어나면서 권한 범위에 대한 투명성이 왜 중요한지 보여주는 사례다.

AI 에이전트나 자동화 통합을 도입할 때 권한 스코프를 얼마나 꼼꼼히 확인해야 하는지 되새기게 하는 글이다.

링크: https://github.com/home-assistant/home-assistant.io/issues/49314
