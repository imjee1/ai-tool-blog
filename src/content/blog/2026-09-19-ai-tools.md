오늘 Hacker News는 AI 코딩 에이전트를 둘러싼 두 가지 상반된 흐름을 보여줍니다. 한쪽에서는 Claude Code가 업계 표준 설정 파일을 채택하며 생태계 통합에 나섰고, 다른 한쪽에서는 중국산 코딩 에이전트 ZCode가 사용자 몰래 Git 히스토리를 업로드한다는 사실이 폭로되며 보안 논란이 커졌습니다. 여기에 LLM과 함께 글을 쓰는 법, 바이브 코딩으로 수학 증명을 검증한 사례까지 더해져 AI 도구를 실제로 어떻게 다뤄야 하는지에 대한 고민이 이어졌습니다.

## Claude Code, AGENTS.md 표준을 받아들이다

Claude Code가 이제 프로젝트에 `CLAUDE.md`가 없으면 `AGENTS.md` 파일을 대신 읽도록 업데이트됐습니다. `AGENTS.md`는 여러 AI 코딩 도구가 공통으로 인식하도록 제안된 파일 형식으로, 도구별로 별도 설정 파일을 만들어야 했던 번거로움을 줄여줍니다. 여러 코딩 에이전트를 함께 쓰는 개발자라면 설정 파일 하나로 통합 관리할 수 있게 됐다는 점에서 실용적인 변화입니다.

- https://code.claude.com/docs/en/changelog

## LLM과 함께 글쓰기, 어떻게 해야 할까

한 개발자가 LLM을 활용해 글을 쓰는 자신만의 워크플로우를 정리한 글입니다. 단순히 초안을 통째로 맡기기보다 문단 단위로 피드백을 주고받거나, 자신의 목소리를 유지하면서 LLM을 편집자·비평가처럼 활용하는 구체적인 방법을 다룹니다. AI를 활용한 글쓰기가 표절이냐 도구 활용이냐는 논쟁이 여전한 가운데, 실전에서 검증된 접근법이라 참고할 만합니다.

- https://sockpuppet.org/blog/2026/09/17/how-to-write-with-an-llm/

## Jemalloc 5.4.0 릴리스

메모리 할당자로 널리 쓰이는 jemalloc의 새 버전이 나왔습니다. 성능 개선과 버그 수정이 포함된 정기 릴리스로, Redis나 Rust 런타임 등 다양한 프로젝트에서 기본 할당자로 채택하고 있어 저수준 성능에 민감한 개발자라면 체크해볼 만합니다.

- https://github.com/jemalloc/jemalloc/releases/tag/5.4.0

## ZCode 코딩 에이전트, 몰래 Git 히스토리를 업로드한다

GLM 기반 코딩 에이전트 ZCode가 사용자 동의 없이 워크스페이스의 Git 히스토리 스냅샷을 클라우드로 전송한다는 사실이 두 개의 독립적인 분석 글을 통해 드러났습니다. 첫 번째 글은 이 문제를 처음 제기하며 구체적인 업로드 동작을 재현했고, 두 번째 글은 실제 네트워크 트래픽을 분석해 어떤 데이터가 어디로 전송되는지 상세히 파헤쳤습니다. 회사 코드베이스나 민감한 커밋 이력이 외부로 유출될 수 있다는 점에서, AI 코딩 도구 도입 전 반드시 네트워크 동작을 점검해야 한다는 경각심을 주는 사례입니다.

- https://tokenstead.ai/guides/zcode-silent-git-history-upload
- https://blog.ferstar.org/en/posts/zcode-silent-workspace-snapshot-upload/

## 바이브 코딩으로 콘웨이 추측 증명하기

리액트 코어 팀 출신으로 유명한 Dan Abramov가 AI와 대화하며 Conway's conjecture 관련 수학 증명을 시도한 경험을 기록했습니다. 정답을 그대로 받아쓰기보다 AI와 함께 가설을 세우고 반박하며 검증해가는 과정을 담았고, 코드가 아닌 수학 증명 영역에서도 바이브 코딩식 접근이 어떻게 작동하는지 보여줍니다. AI를 정답 기계가 아니라 사고를 확장하는 파트너로 쓰는 사례라는 점에서 흥미롭습니다.

- https://overreacted.io/how-i-vibed-a-proof-of-conways-conjecture/

## 8~29MB 초경량 모델이 DeepSeek V4 Flash와 맞먹는다?

Cactus Compute가 공개한 "Needle 3"는 자동화 작업에 특화된 8~29MB 크기의 초경량 모델로, 특정 벤치마크에서 훨씬 큰 DeepSeek V4 Flash와 비슷한 성능을 낸다고 주장합니다. 온디바이스나 엣지 환경에서 돌아갈 정도로 작은 크기라는 점이 핵심 세일즈 포인트입니다. 거대 모델 없이도 특정 작업에 특화된 소형 모델로 실용적인 자동화가 가능하다는 방향성을 보여주는 사례입니다.

- https://cactuscompute.com/needle

## 가상화 없이 Linux에서 Wine으로 MS Office 돌리기

Wine을 이용해 가상머신이나 컨테이너 없이 Linux에서 Microsoft Office 365를 실행하는 방법을 정리한 프로젝트입니다. Nix flake로 설정을 패키징해 재현 가능한 환경을 제공합니다. Office 의존성 때문에 Linux 전환을 망설이던 개발자들에게는 실질적인 대안이 될 수 있는 시도입니다.

- https://github.com/Tombert/office365_flake
