오늘 Hacker News는 AI 관련 실용적인 논의가 눈에 띄었습니다. LLM 라우터를 만들었다가 오히려 없애기로 한 회사의 회고, 증류(distillation) 과정에서 검열이 전달되지 않는다는 실험 결과, 그리고 AI 에이전트를 위한 GUI는 어떤 모습이어야 하는지에 대한 질문까지 - AI를 실제로 프로덕션에 적용하면서 마주치는 현실적인 고민들이 주를 이뤘습니다. 여기에 Go 언어의 제네릭 컬렉션 제안이나 하드웨어 최적화 이야기도 함께 화제가 됐습니다.

## Show HN: DeepSeek을 GPT-OSS로 증류해도 검열은 전달되지 않는다

CTGT 팀이 DeepSeek 모델의 지식을 GPT-OSS로 증류(distillation)하는 실험을 진행한 결과, 원본 모델에 있던 검열 성향이 증류된 모델로 전달되지 않는다는 것을 발견했습니다. 직접 테스트해볼 수 있는 데모도 함께 공개했습니다. 모델 증류가 단순히 능력만 옮기는 게 아니라 학습 데이터의 편향/제약도 함께 옮긴다는 통념에 반하는 결과라 흥미롭습니다.

증류 과정에서 정확히 무엇이 전달되고 무엇이 걸러지는지에 대한 이해는 오픈소스 모델 파인튜닝 전략에 실질적인 영향을 줄 수 있어 주목할 만합니다.

원문: https://www.ctgt.ai/research/distillation-censorship-transfer

## Show HN: AI 에이전트를 위한 GUI는 어떻게 생겨야 할까

Marble OS가 AI 에이전트 전용 인터페이스에 대한 데모를 공개했습니다. 지금까지의 챗봇 UI가 아니라, 에이전트가 여러 작업을 수행하고 상태를 관리하는 것을 사람이 자연스럽게 감독할 수 있는 새로운 형태의 GUI를 제안합니다. LLM 기반 에이전트가 실무에 투입되면서 "대화창"만으로는 부족하다는 문제의식이 반영된 시도입니다.

에이전트가 백그라운드에서 여러 작업을 동시에 처리하는 시대에, 사용자 인터페이스 설계 자체가 새로운 챌린지로 떠오르고 있음을 보여주는 사례입니다.

원문: https://marbleos.com/demo

## LLM 라우터를 만들었다가 없앤 이유

Manifest 팀은 여러 LLM 중 요청에 맞는 모델을 자동으로 선택해주는 라우터를 만들었지만, 결국 이를 폐기했다고 밝혔습니다. 모델 간 성능 격차가 좁아지고 비용 구조가 변하면서, 복잡한 라우팅 로직을 유지하는 것보다 단순하게 하나의 강력한 모델을 쓰는 게 더 실용적이었다는 것이 요지입니다. 많은 회사들이 LLM 라우터를 경쟁적으로 개발하는 트렌드와 정반대의 결론이라 눈길을 끕니다.

라우터 도입을 고민 중인 팀이라면, 복잡도 대비 실제 이득을 다시 따져볼 만한 인사이트를 제공합니다.

원문: https://manifest.build/blog/why-we-deprecated-our-llm-router/

## 10GB RAM으로 10억 규모 그래프 알고리즘 돌리기: DataFusion 활용기

저자는 Apache DataFusion을 활용해 10GB의 적은 메모리로도 10억 스케일의 그래프에서 알고리즘을 실행한 경험을 공유합니다. 컬럼 기반 쿼리 엔진의 스트리밍 처리 방식을 그래프 알고리즘에 적용한 실전 사례로, 구체적인 구현 방법과 성능 특성을 다룹니다. 대규모 데이터를 다뤄야 하지만 인프라 비용은 제한적인 상황에 있는 개발자들에게 실질적인 참고가 됩니다.

메모리 제약 환경에서 대규모 그래프 처리가 필요한 데이터 엔지니어링 팀에게 실용적인 선택지를 제시한다는 점에서 주목할 만합니다.

원문: https://semyonsinchenko.github.io/ssinchenko/post/datafusion-graphs-cc-2/

## 기타 화제: Go 컬렉션 제네릭 제안, Mac Thunderbolt 네트워킹, NAT 우회 도구

Go 언어에 `container/` 패키지로 제네릭 컬렉션 타입을 추가하자는 공식 제안이 활발한 토론을 이끌었습니다(https://github.com/golang/go/issues/80590). Jeff Geerling은 Mac Studio에서 Thunderbolt를 통해 25Gbps 이더넷을 구현한 과정을 상세히 정리했습니다(https://www.jeffgeerling.com/blog/2026/getting-25g-ethernet-mac-thunderbolt/). 그리고 BitBang은 계정 없이 브라우저에서 NAT 뒤에 있는 기기에 접근할 수 있는 CLI 도구로 소개됐습니다(https://github.com/richlegrand/bitbang-cli).

이 외에도 `qm`이라는 프로젝트가 383점으로 가장 높은 관심을 받았으나 구체적인 설명 없이 GitHub 저장소만 공개된 상태로, 커뮤니티의 관심과 별개로 상세한 내용은 저장소를 직접 확인해보시길 권합니다(https://github.com/yc-software/qm).
