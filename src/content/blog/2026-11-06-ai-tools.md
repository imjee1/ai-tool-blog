오늘 Hacker News에서는 AI 코딩 에이전트의 보안과 신뢰 문제가 가장 뜨거운 화두였습니다. Claude Code의 데이터 전송 이슈가 큰 논쟁을 불러일으켰고, 동시에 에이전트를 감사(audit)하고 관리하는 도구들도 관심을 받았습니다. 한편 텐센트는 새로운 오픈소스 AI 모델을 공개하며 오픈소스 LLM 경쟁에 다시 불을 지폈습니다.

## Claude Code가 이메일 주소를 외부 웹사이트로 전송한다는 이슈

Anthropic의 Claude Code GitHub 저장소에 올라온 이슈로, Claude Code가 사용자 동의 없이 이메일 주소를 특정 웹사이트에 전송한다는 보고가 601점이라는 높은 추천수와 202개의 댓글을 받으며 큰 화제가 됐습니다. 정확한 전송 경로와 용도를 두고 커뮤니티에서는 프라이버시 침해 소지부터 단순 버그까지 다양한 해석이 오가고 있습니다. AI 코딩 도구를 업무에 도입한 개발자라면 어떤 데이터가 외부로 나가는지 한 번쯤 점검해볼 필요가 있어 보입니다.

원문: https://github.com/anthropics/claude-code/issues/107757

## 텐센트, 오픈소스 AI 모델 Hy4 공개

텐센트가 세계 최고 수준의 오픈소스 AI 모델 대열에 합류했다고 발표한 Hy4 모델입니다. 공식 발표문에서는 성능과 공개 범위를 주요 특징으로 내세우고 있으며, 오픈소스 LLM 생태계에 중국 빅테크의 참여가 계속 확대되는 흐름을 보여줍니다. 오픈소스 모델 선택지가 늘어나는 것은 비용과 커스터마이징 측면에서 개발자들에게 실질적인 이점이 될 수 있습니다.

원문: https://www.tencent.com/tencent-launches-hy4-joining-the-ranks-of-the-worlds-leading-open-source-ai-models/

## Rivet – S3 기반으로 에이전트를 확장하고 오케스트레이션하는 도구 (YC W23)

Rivet은 AI 에이전트를 S3를 활용해 대규모로 확장하고 오케스트레이션할 수 있도록 설계된 오픈소스 프로젝트입니다. YC W23 배치 출신 팀이 공개한 Launch HN 게시물로, 에이전트 워크로드를 분산 처리하는 인프라 문제에 집중하고 있습니다. 에이전트를 프로덕션 환경에서 대규모로 운영해야 하는 팀이라면 참고할 만한 아키텍처 사례입니다.

원문: https://github.com/rivet-dev/rivet

## Stroq – 코딩 에이전트의 작업 내역을 로컬에서 감사하는 도구

Stroq는 AI 코딩 에이전트가 수행한 작업과 그 이유를 로컬 환경에서 감사(audit)할 수 있게 해주는 Show HN 프로젝트입니다. 외부 서버로 데이터를 보내지 않고 로컬에서 작업 기록을 추적한다는 점이 특징입니다. 위의 Claude Code 이슈처럼 에이전트의 행동을 신뢰하기 어려운 상황에서, 이런 로컬 감사 도구의 필요성이 더 설득력 있게 다가옵니다.

원문: https://github.com/AGGIB/Stroq

## "AI 에이전트와 일하려면 강철 멘탈이 필요하다"

AI 에이전트를 실무에 도입하며 겪은 좌절과 예측 불가능성을 다룬 에세이 형식의 글입니다. 작성자는 에이전트가 예상과 다르게 행동하거나 의도치 않은 결과를 내는 경험을 공유하며, 이를 다루는 개발자의 심리적 피로감을 토로합니다. 81개의 댓글에서 많은 개발자들이 비슷한 경험을 공유하며 공감대를 형성한 점이 흥미롭습니다.

원문: https://orchidfiles.com/youll-need-nerves-of-steel-to-work-with-ai-agents/
